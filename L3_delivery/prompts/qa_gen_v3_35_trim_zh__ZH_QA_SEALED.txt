请阅读【文档】，生成 {min_pairs} 到 {max_pairs} 组接近官方 Ultra-FineWeb-L3 中文风格的问答，只输出合法 JSON。

总体目标：
- 像官方网页 QA，而不是教材题库、阅读理解解析或提纲总结。
- 问题短、具体、自足，围绕正文显式信息锚点；答案忠实、简洁、可逐句定位。
- 直接事实题是主体，但不能退化成“是什么/有哪些”的抽取清单。只要证据明确，应自然加入判断题、选择题、原因题、比较题或条件题。
- 答案要有学习价值：直接事实题也尽量用完整短句作答，保留主语或限定；不要大量只回一个数字、名称或短语（除非原文本身就是纯数字/名称/选项）。结构题在结论之后补一句最短依据或作用。
- 安全不是少问：如果某个复杂题不稳，优先改成同一信息点上的可答事实题或保守判断题，尽量保持问答数量接近要求范围。
- 不要问“这句话属于什么题型”“是否是判断题/选择题/简答题”这类元问题。

先在内部选择信息锚点，不要输出过程：
- 优先覆盖正文最显眼的核心事实、人物/机构/地点/时间、数字/参数/步骤、条件/因果/对比、例外限制、首尾结论。
- 高显著锚点优先级（内部排序，不输出）：标题或首段点出的核心主题 > 开头交代的目的/诉求 > 核心事实与关键数字 > 显式因果/对比关系 > 有效的结尾结论或表态。正文明确给出这些时，尽量不要让整篇 QA 只停在分散的表层细节上。
- 每组 QA 只问一个清楚焦点；不要把多个无关数字或多个相邻卖点揉成一个结论。
- 若标题或题干出现“A 与 B 的区别/比较”，但正文只说明 A：优先问 A 的具体信息；必要时可问“正文是否说明 B 的信息”，答案写“未说明/不能确定”，不得补 B 的常识。
- 若原文有明确的限制词、例外词或不确定词，如“除了、仅、可能、疑似、估计”，问题和答案都要保留这些边界。

先在内部判断文档类型，不要输出判断过程：
- 新闻/人物/活动：优先人物、时间、地点、事件、活动内容、规则、成就、结果；除时间地点外，可自然补 1 题活动性质、目的或规则。
- 知识/说明/科普/技术：优先定义、功能、作用、参数、方法、条件、区别；只问原文给出的工程关系，不补术语常识。
- 列表/流程/参数：优先关键项、顺序、分类、数值、命令、选项。
- 表格/排名/天气月历：必须锁定表名、指标列、排名范围和日期范围；多个表相邻时，禁止跨表取值。
- 目录/索引：只问章节、条目、页码、是否列出、相邻主题；不要解释章节名背后的专业功能。
- 试题/题目列表：把题库当成题库，不要当普通正文。若原文给出了答案或解析，可转成“正确选项/正确答案 + 一句依据”；若原文未给答案，只问题干给出的条件、对象、题型或选项内容，绝不替题解答，也不要引入外部知识。不要写“题目X中/第X题里”这类元引用式问法，直接就题目内容发问。
- 教材练习/组词/比一比：只问题干给了哪些字词、要求怎么组词、原文列出了哪些搭配；不要把形近字组词题改成近义词、语义相近或概念辨析题，也不要把“屡次/缕”这类组词练习误写成语义辨析。
- 符号化提纲/公式/箭头关系：只按字面符号和层级出题；公式 A×B+C 理解为 (A×B)+C，不要把箭头自造为因果链。问章节号时必须逐字引用原文中的节号和标题，不要把 2.1.18 写成 3.1.8 这类相近编号。
- 图文标题流/无图片内容：只问文字标题、提示语、作品名或出现的问句；没有图片时，不能断言画中实际隐藏了什么，也不要分析疑问句的题型，更不要问“第一眼看到了啥”“是否给出了具体答案”这类元问题，也不要问文末“在看”、分享、转发、扫码、关注、备用号这类尾巴。
- 评论/散文/歌词/短句：只问明确写到的人物、态度、关系、行为和直观情绪；若正文有明确的意象、态度、情绪或人物对照，可自然加 1 题语境或态度题，但依据必须来自原文明确的句子。不要升华成哲理、人格或生活态度，不要补出“梦想、勇气、清醒、自我意识、支持决定”这类原文没明说的心理解释。
- 包装/营销/联系人/广告噪声：忽略扫码、关注、转发、福利、客服、备用号、页脚；若有知识或教育主体，优先问主体价值；价格、电话只在核心规则时浅问；联系人列表只做浅层名称抽取，不强行归类行业或业务。

题型策略：
1. 直接事实题为主。
   - 问实体、时间、地点、数量、名称、功能、步骤、原因、结果。
   - 问题自然具体，不要把原文整段塞进题干。
   - 直接事实题的答案默认用完整短句，保留主语或限定；纯数字/名称/选项题可短。
   - 事实题也尽量问得有层次：在原文证据充分时，优先用“……请结合原文说明”“文中列出了哪些……（请一并列出）”“A 与 B 相比是更……还是更……”这类需要聚合、比较或给出依据的问法，而不是每题都只问单个实体/数字。但这只在原文信息足够支撑时使用；信息不足就老实问单点事实，绝不为“显得有层次”而给答案注水、硬凑比较或引入原文没有的内容。忠实与可定位优先于层次感。
2. 判断题要自然出现。
   - 文中有真假、是否、能否、适合/不适合、对/错、已列出/未列出关系时，优先转成判断题。
   - 判断题必须判断一个原文事实、原文明示关系或“正文未说明”的边界；不得判断题型、句式或阅读行为。
   - 答案先写“正确/错误/不能确定/未说明”，再给一句短依据。
3. 为什么/原因题谨慎但不要完全回避。
   - 只在原文明确给出“因为、由于、为了、作用、导致、使、从而、以便、目的是”等关系时使用。
   - 答案先给结论，再补最短因果依据；不能加入常识原因或主观动机。
4. 选择题要可验证。
   - 选择题题干必须包含 A/B/C/D 四个选项；不要写“下列哪项”却不给选项。
   - 单选题只能有一个最合理答案；若多个选项都可由原文支持，改成多选题或事实题。
   - 干扰项只做同语境近似，不引入外部知识，也不要把原文中另一个真实事实放进单选干扰项。
   - 答案先写正确选项内容，再用一句短依据说明；不要只写“任一均可”。
5. 比较/条件题少量使用。
   - 只在原文明确提供比较对象、条件或前后关系时使用。
   - 若比较对象不完整，改问已给出的对象，或明确回答“正文未提供另一对象的信息”。
   - 只做一跳推理，不要复杂计算或多步演绎；不得自设数字。
6. 主旨/概括题（可选，仅在证据充分时）。
   - 若正文有明确的主题句、结尾结论或总结句，可问“全文主要说明了什么/结尾得出的结论是什么”，答案只复述原文明确表达的主旨，不升华、不外推。

题型多样是硬要求（官方风格核心，必须达成）：
- 直接事实题不得超过总题数的一半；整篇绝不能只是“抽取一个实体/数字/名称”的单点题堆叠。
- 每篇在证据允许时，应尽量包含：至少 1 道判断题（对/错/未说明 + 依据），至少 1 道选择题（A/B/C/D 四选项、单选唯一），以及至少 1 道原因题或综合推算题（如根据原文数据做一步推算：日期、年龄、时长差等）。
- 若原文本身就是题库/选择题材料，优先直接把它做成带 A/B/C/D 的选择题（含正确项+依据），而不是问“题目X的选项Y说了什么”这类元引用题。
- 这些题型要求以忠实为绝对前提：只有原文证据明确支持时才出该题型；若某题型确无证据支撑，可少出该类，但不得为凑题型而编造关系、套模板或引入原文没有的事实。忠实优先级高于题型配额。

特殊源文硬约束：
- 目录/索引：不能问“为什么需要保持型定时器”“闭环控制有什么原理”这类章节名外推；只能问“属于哪章/哪节/页码/是否列出”。
- 试题/题目列表：不能求出物理题答案、炸药工艺答案、公式答案；可以问“该题给出的初速度是多少”“题目要求写出哪两类几何体关系式”；若原文附了答案或解析，可问“正确答案是哪个及依据”。
- 教材练习/组词：遇到“比一比、组词、选字填空、形近字”时，答案只复述原文给出的字词、搭配或题目要求；不要回答“两个词含义相近/不同”，除非原文已经解释含义。
- 表格/排名：问题中必须写明“空气质量全国最差10城排名”“月历”等表名或范围；答案只能来自同一表的同一指标列。
- 图文标题流：可以问“文中出现了哪些提示语/这组画叫什么名字”，不能答“画中隐藏的是人脸之一”或“画面里确实有某物”，也不能生成元问题，更不要问“文末点亮【在看】”这类互动尾巴。
- OCR/小数/单位：遇到“1倍。5倍”“35．4MP”等残缺或易误读数字，优先逐字引用原文；不要擅自改成“五倍”“1.5倍”或做单位换算。只要原文像 OCR 断裂，就按原片段答，不要替它“修正”成更顺的数字。
- 相对时间：若原文只写“今年5月底/本月”，答案保留原文说法，并补“原文未给出具体年份/月基准”；若不能补上下文，就避免出这题。
- 技术文本：NPSHr 小只能答“吸入性能高/很小的 NPSHr 值”；“泵送液体作为密封液”不能扩写成“无需润滑”；“无搅拌/无脉动”和“密封液/自吸”等相邻卖点不要揉成因果。
- 编程/术语区别：若题干提到 A 与 B，但正文只解释 A，只能回答 A 的定义、作用、限制，或说明正文未提供 B 的信息；不得补充 B 的运行时行为或外部知识。
- 主体一致性：答案里的主语必须能在同一句或相邻明确指代范围内找到；不要把“以黑格尔为代表的哲学家们”的观点归给“德国历史学派经济学家”，也不要把“四个游戏”写成“四位嘉宾”。
- 情绪/歌词/短句：可以概括“思念、离别、不舍、悲伤”，不要扩展为“自律生活态度、对抗虚无、赋予生命意义”等原文没有的抽象判断。

数量建议：
- 3-4 组：2-3 个事实题 + 1 个结构题。
- 5-6 组：至少 2 个结构题（判断/为什么/选择/比较/条件/主旨之一）。
- 7-8 组：通常应包含判断题、原因题或比较题；信息足够且选项唯一时再加 1 个选择题。
- 不要强行把每篇都做成同一种结构，也不要每篇都追求复杂题。

答案风格：
- 多数答案 1-2 句；结构题可略长一点，但不要写成解析段。
- 不要频繁使用“根据文本/文中明确指出”作为固定开头。
- 不要加入原文没有的背景、常识推断、评价、动机或结论。

内部后检，不要输出：
- 每个答案必须能在原文逐句定位；不能定位就改成同一信息点上的可答事实题、保守判断题或删除。
- 最终 qa_pairs 数量必须落在 {min_pairs} 到 {max_pairs}；删除不安全题后，优先补充可定位的信息锚点。
- 选择题必须有 A/B/C/D，且单选唯一。
- 判断题极性必须和证据一致，且判断对象必须是原文事实或原文信息边界。
- 问题里的“这个/该/其/前者/后者/上述/此”必须有明确对象。
- 若原文是结构化文本，只使用显式关系，不自造散文式因果链。
- 检查答案主语与原文证据主语是否一致；若主语跨句迁移会引起歧义，改成更具体的主语或删除。
- 检查是否整篇都是单点短答：若是且正文本可支撑更完整的答案或关系题，适度补足答案完整性或替换 1 题为关系题（在忠实前提下）。

严格禁止：
- 不得把正文改成教材提纲、议论文或长解释。
- 不得围绕广告、扫码、关注公众号、点在看、在看、转发、福利、客服、推荐阅读、页脚噪声出题。
- 不得生成关于题型本身的元问题。
- 不得编造文档没有的人名、机构、时间、数字、原因、结果。
- 不得为了选择题硬造陌生知识。
- 不得输出 markdown、解释文字或 JSON 之外的内容。

输出格式必须严格如下：
{
  "qa_pairs": [
    {"question": "...", "answer": "..."}
  ]
}

JSON 要求：
- 只输出一个 JSON 对象。
- `question` 和 `answer` 都必须是字符串。
- 字符串内部如需换行，必须写成 \n。
- 所有引号必须闭合。
