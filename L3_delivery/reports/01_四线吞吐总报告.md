## 口径说明（读表前必看）
- **QA 每篇 1 次 LLM 调用**（content = 原文 + 问答对，原文在前）。
- **rewrite 每篇 4 次调用**（4 风格：encyclopedia/textbook/blog/abstract）。
- 所以「篇/分」跨线不可直接比，需看「调用/分」才同口径。
- 墙钟取 tqdm `[MM:SS]`（真实墙钟），非 run_stats 的 elapsed_seconds（那是调用耗时累加）。
- 吞吐 = 有效篇数（种子过滤后实际进入合成）÷ 墙钟。

## 二、并发拐点（生产定档依据）

| 线 | 并发对比 | 加速比 | 生产定档 |

**规律**：QA token 省、拐点靠后（c16 最优）；rewrite 每篇 4 调用、token 重、拐点靠前（c8 最优）。
两类任务生产并发不通用：**QA = 16、rewrite = 8**。

## 三、prefix caching（仅英文 rewrite 侧实测）
- 8003 加 `--enable-prefix-caching` 重启后，英文 rewrite c8：10.33→11.31 篇/分（**+9.5%**）。
- 固定 system 前缀 ~1384 token（占每请求 66%）被复用，实测 ~37% token 命中缓存跳过 prefill。
- 未到 66% 理论上限：冷启动 + c8 高并发下 KV 驱逐。缓存省算力/时间，不省 token 计费。
- 生产建议：开缓存无害且免费（仅重启加 flag），长期常开。

## 四、同口径横向对比（调用/分）
- 英文 QA c16 = 62.0 调用/分（单次吞吐最高，QA 输出短、token 省）。
- 中文 rewrite c8 = 54.3、英文 rewrite c8+cache = 45.2 调用/分。
- 中文 QA c16 = 53.1 ≈ 中文 rewrite c8 = 54.3 —— 单次调用吞吐两线接近，
  跨线「篇/分」差异主要来自「每篇几次调用」和 prompt 轻重、语言 token 效率。

## 五、成功率与坏数据
- 全部 11 个批次**坏数据 = 0**：schema 100% `{uid,content,style}`、0 个 `<think>` 残留、
  QA 段 0 占位符（英文 QA c8 扫到的 20 处 `...` 逐条核为原文正文合法省略号，非坏占位符）。
- QA 成功率 ≥0.98，rewrite ~0.95。少量失败均为：
  - QA：max_tokens 截断致 JSON 不完整，被 parse_qa 如实拒绝；
  - rewrite：模型偶发不包 JSON 外壳 `{"content":...}`（推理模型指令遵循弱），被 parse_rewrite 丢弃。
  - 均为安全网正常工作，**非坏数据落盘**。

1. 四条线（中/英 × QA/rewrite）在 5090 上均跑通并封板：吞吐/稳定性达标、零坏数据、
